# 🏪 Телегинс Шоп - Подробная документация о функциях

## 📋 Обзор проекта

**Телегинс Шоп** - это современный интернет-магазин хозяйственных товаров с интеграцией с системой учёта МойСклад, системой кэширования Redis и продвинутой системой управления остатками.

---

## 🚀 Основные функции

### 📦 Каталог товаров
- **Поиск по каталогу** - полнотекстовый поиск товаров с поддержкой пагинации
- **Фильтрация по категориям** - возможность фильтровать товары по категориям
- **Умная пагинация** - система автоматически добирает товары при фильтрации по остаткам
- **Детальная информация** - полная информация о товаре включая описание, цену, остатки

### 🛒 Корзина и заказы
- **Добавление в корзину** - с проверкой доступных остатков в реальном времени
- **Резервирование товаров** - товары резервируются в корзине на 30 минут
- **Обновление количества** - динамическое изменение количества с проверкой остатков
- **Оформление заказа** - создание заявки с автоматическим освобождением резервов

### 👤 Пользовательская система
- **Простая регистрация** - без email-верификации (оптимально для локального развертывания)
- **JWT-аутентификация** - безопасные токены с временем жизни 24 часа
- **Защита от ботов** - honeypot поле для предотвращения автоматической регистрации
- **Профиль пользователя** - просмотр и управление личными данными

### 🎯 Акции и promotions
- **Создание акций** - администратор может создавать promotional акции
- **Отображение на главной** - активные акции показываются на главной странице
- **Управление сроками** - контроль времени начала и окончания акций

## 🔧 Технические особенности

### ⚡ Система кэширования Redis

**Время жизни кэша:**
- **Остатки товаров:** 30 минут
- **Резервирования:** без TTL (хранятся до освобождения)
- **Время синхронизации:** кэшируется навсегда

**Функции кэша:**
```go
// Основные операции
SetStock(ctx, productID, moyskladID, stock)     // Кэширование остатка
GetStock(ctx, productID)                       // Получение остатка
GetAvailableStock(ctx, productID, query)        // Доступный остаток (факт - резерв)
ReserveStock(ctx, productID, quantity)          // Резервирование товара
ReleaseStock(ctx, productID, quantity)          // Освобождение резерва

// Массовые операции
BatchSetStocks(ctx, products)                   // Массовое кэширование
InvalidateStockCache(ctx, productID)            // Инвалидация кэша
InvalidateByMoyskladID(ctx, moyskladID)         // Инвалидация по ID МойСклад
```

**Буфер остатков:**
- По умолчанию: **5%** от общего количества
- Настраивается через переменную `MOYSKLAD_STOCK_BUFFER`
- Предотвращает продажу товаров с нулевыми остатками из-за задержек синхронизации

### 🔄 Интеграция с МойСклад

**Настройки:**
- **Базовый URL:** `https://api.moysklad.ru/api/remap/1.2`
- **Лимит запросов:** 2 запроса в секунду (настраивается)
- **Макс. попыток:** 3 повторных попытки при ошибках
- **Интервал синхронизации:** 10 минут (настраивается)

**Режимы синхронизации:**
1. **Полная синхронизация** - все товары
2. **Дельта-синхронизация** - только измененные товары
3. **Автоматическая синхронизация** - по расписанию
4. **Webhook-синхронизация** - мгновенные обновления

**Rate Limiting:**
```go
// Контроль частоты запросов
requestsPerSecond := 2.0  // 2 запроса/сек
minInterval := 1000/2.0   // 500ms между запросами
```

### 📊 Управление остатками

**Система трёх уровней:**
1. **Общий остаток** - фактическое количество на складе МойСклад
2. **Доступный остаток** - общий остаток минус зарезервированные товары
3. **Буферный остаток** - доступный остаток минус буфер (5%)

**Пример расчёта:**
```
Общий остаток: 100 шт
Зарезервировано: 15 шт
Доступный остаток: 85 шт
Буфер (5%): 4.25 шт
Доступно для продажи: 80.75 ≈ 80 шт
```

## 🔐 Безопасность

### 🛡️ Middleware защиты
1. **Security Headers** - HTTP заголовки безопасности
2. **CORS** - настройка кросс-доменных запросов
3. **Rate Limiting** - ограничение частоты запросов
4. **CSRF Protection** - защита от межсайтовой подделки
5. **Input Sanitization** - санитизация входных данных

### 🔑 JWT Аутентификация
- **Секретный ключ:** настраивается через `JWT_SECRET`
- **Время жизни:** 24 часа (настраивается)
- **Алгоритм:** HS256
- **Claims:** user_id, username, email, exp

### 🤖 Защита от ботов
- **Honeypot поле:** `website` в форме регистрации
- **Проверка сложности пароля:** минимум 8 символов
- **Логирование подозрительной активности**

## 🚀 Производительность

### ⚡ Оптимизации
1. **Кэширование остатков** - Redis кэш на 30 минут
2. **Пагинация** - эффективная загрузка больших списков
3. **Rate Limiting** - защита от перегрузки
4. **Connection Pooling** - пул соединений с БД
5. **Graceful Shutdown** - плавное завершение работы

### 📈 Метрики производительности
- **Время ответа API:** < 100ms (с кэшем)
- **Время синхронизации:** ~2-5 минут для 1000 товаров
- **Потребление памяти:** ~50-100MB (зависит от количества товаров)
- **CPU нагрузка:** минимальная при работе с кэшем

## 🔄 Процессы

### 📅 Автоматическая синхронизация
```bash
# Запускается каждые 10 минут
cron: */10 * * * * /app/sync_moysklad

# Процесс:
1. Получение товаров из МойСклад
2. Обновление БД
3. Инвалидация кэша
4. Логирование результатов
```

### 🛒 Процесс оформления заказа
```
1. Пользователь добавляет товары в корзину
2. Товары резервируются в Redis
3. Пользователь оформляет заказ
4. Резервы освобождаются
5. Заказ сохраняется в БД
6. Опционально: отправка в МойСклад
```

### 🔄 Процесс синхронизации остатков
```
1. Запрос остатков из МойСklad API
2. Применение буфера (5%)
3. Кэширование в Redis
4. Обновление доступных остатков
5. Инвалидация старого кэша
```
